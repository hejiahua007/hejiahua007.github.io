这个网站最早建于毕业前，用来记录嵌入式学习、毕业设计和日常思考。工作一年半后再回头看，它保留了很多真实的成长痕迹，但作为简历网站已经不能准确表达现在的能力。因此，我开始把它从“学生时期的技术博客”升级为“个人作品集 + 技术博客”。

## 本次优化目标

- 让访问者快速了解我的职业方向和技术能力。
- 把毕业后的练习项目整理成结构清晰的作品集。
- 保留毕业前文章，继续展示完整的学习轨迹。
- 建立统一的项目日志、技术笔记和生活记录规范。
- 修复旧仓库结构、构建流程和内容展示问题。

## 已完成的工作

### 1. 重构首页

首页不再只显示文章列表，而是围绕职业定位重新组织：

- 工业桌面端开发
- 设备通信与数据处理
- AI 视觉检测
- 垂直领域 AI 应用

同时增加项目、在线简历和 GitHub 的直接入口，让招聘者能够快速找到核心内容。

### 2. 新增项目作品集

根据现有练习项目整理了以下案例：

- 工业质量检测客户端
- 自动分拣控制客户端
- 焊缝 AI 视觉检测
- PA Agent
- 智能睡眠助手

项目描述重点放在技术架构、实际问题和工程实践上。部分工业背景经过场景化整理，只用于展示技术能力。

### 3. 更新在线简历

删除了已经过期的学生简历结构，改为工作方向、工作经历、技术能力、代表项目和教育经历，并降低手机号等非必要个人信息的曝光。

### 4. 修复文章无法展示的问题

旧文章原本存放在：

```text
_posts/_posts/
```

Jekyll 的标准文章目录应该是：

```text
_posts/
```

因此线上只能识别位于正确目录中的一篇文章。本次将旧文章迁移到标准目录，并把日期统一为 `YYYY-MM-DD` 格式，使分类、标签和归档页面能够正常收录。

### 5. 整理图片资源

文章图片从 `_posts/assets/blog_res/` 迁移到公开资源目录 `assets/blog_res/`，继续使用 `/assets/blog_res/...` 形式引用，避免文章发布后找不到图片。

### 6. 更新部署流程

当前网站的发布流程是：

```text
main（源码） → GitHub Actions 构建 → gh-pages（静态网站） → GitHub Pages
```

`main` 用来保存 Markdown、配置和页面源码；`gh-pages` 由自动化脚本生成，不应该手工编辑。以后只需要向 `main` 提交内容。

## 后续内容如何存放

所有需要出现在首页、分类、标签和归档中的内容，都放在 `_posts/` 下，文件名必须采用：

```text
YYYY-MM-DD-英文或拼音标题.md
```

文章开头至少包含：

```yaml
---
title: 文章标题
date: 2026-07-11 12:30:00 +0800
categories: [一级分类, 二级分类]
tags: [标签一, 标签二]
---
```

建议分类如下：

| 内容类型 | categories 示例 | 用途 |
| --- | --- | --- |
| 项目开发记录 | `[项目日志, 项目名称]` | 记录需求、实现、问题和复盘 |
| 每日简短记录 | `[每日日志]` | 记录当天进展和想法 |
| 技术学习笔记 | `[技术笔记, Python]` | 可长期检索的技术内容 |
| 生活与阅读 | `[生活记录]` | 工作之外的个人成长 |

图片统一放在：

```text
assets/blog_res/YYYY-MM-DD-文章名称/
```

文章中使用：

```markdown
![图片说明](/assets/blog_res/YYYY-MM-DD-文章名称/image.png)
```
