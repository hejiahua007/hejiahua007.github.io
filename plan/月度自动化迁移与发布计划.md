# 月度迁移与发布计划（最小版）

> 版本：v2.0  
> 状态：先手动运行两个月，再决定是否调度  
> 唯一目标：每月底安全完成 `life-vault → 本地长期 Vault → 公开网站` 闭环

## 1. 本期只做什么

每月底完成六件事：

1. 拉取最新 `life-vault`；
2. 生成源文件清单；
3. 让迁移智能体只输出分类路由 JSON；
4. 由脚本验证并复制，源文件暂不删除；
5. 让整理智能体只整理本次复制的 Markdown；
6. 人工确认 `published` 后安全发布，再清理 `life-vault`。

本期不做：

- Electron 或管理后台；
- 自动定时运行；
- 让模型直接删除、提交或推送；
- 自动决定哪些内容公开；
- 一次性重命名整个历史 Vault；
- 自动建设知识图谱、技能图谱或人生时间线。

## 2. 一个内容源

| 位置 | 职责 |
|---|---|
| `life-vault/_vault/` | 当月工作区，月底清理 |
| `hejiahua007.github.io/_vault/` | 宿舍电脑上的长期主库，也是网站内容源 |
| `hejiahua007.github.io/_posts/` | 旧内容过渡区，不再新增 |
| GitHub Pages | 只展示明确 `published: true` 的 `_vault` 内容 |

网站层级完全来自 `_vault/A*/B*/C*/` 文件夹。`categories` 可省略，由构建插件推导。

## 3. AI 与脚本的责任边界

### 迁移智能体

- 读取 inventory 和源文件；
- 为每个文件选择 `migrate` 或 `retain`；
- 给出目标路径、理由和置信度；
- 只写 `routing-plan.json`。

提示词：[agents/migration-agent.md](../agents/migration-agent.md)

### 整理智能体

- 只处理 applied manifest 中的 Markdown；
- 删除重复表达和格式噪音；
- 保留事实、失败尝试、结论和证据；
- 缺少 `published` 时只能补 `false`；
- 不清理源仓、不操作 Git。

提示词：[agents/curation-agent.md](../agents/curation-agent.md)

### 确定性脚本

- 路径不能越界；
- 哈希必须一致；
- 目标不同内容时禁止覆盖；
- Apply 前建立本地源备份；
- 只有明确确认才能删除源文件；
- 只有明确 `published: true` 才能暂存发布。

## 4. 每月底执行步骤

以下命令均在 `hejiahua007.github.io` 根目录执行。

### 步骤 1：同步源仓库

```powershell
git -C ..\life-vault status --short
git -C ..\life-vault pull --rebase
```

存在未提交改动或冲突时停止，不自动 stash。

### 步骤 2：生成迁移输入

```powershell
.\tools\monthly-migration.ps1 -Mode Prepare -MigrationId 2026-08
```

生成：

```text
.migration/2026-08/inventory.json
.migration/2026-08/routing-plan.template.json
```

`.migration/` 被 Git 忽略，因为里面可能包含私人内容。

### 步骤 3：调用迁移智能体

向模型提供 `agents/migration-agent.md`，让它生成：

```text
.migration/2026-08/routing-plan.json
```

低成本模型若不确定，必须输出 `retain`，不能猜测。

### 步骤 4：验证并复制

```powershell
.\tools\monthly-migration.ps1 -Mode Apply -MigrationId 2026-08
```

Apply 会先完整预检，再复制并生成：

```text
.migration/2026-08/applied-manifest.json
.migration/2026-08/source-backup/
```

此时 `life-vault` 不会被删除或改动。

### 步骤 5：调用整理智能体

向模型提供 `agents/curation-agent.md`。完成后运行：

```powershell
.\tools\validate-vault.ps1 -ChangedOnly
.\tools\safe-publish.ps1 -DryRun
```

### 步骤 6：人工确认并发布

人工检查：

- `git diff`；
- 每个待公开文件的 `published: true`；
- 图片是否存在；
- 整理稿是否产生幻觉或丢失事实；
- 发布预览数量是否合理。

确认后：

```powershell
.\tools\safe-publish.ps1
git diff --cached --stat
git diff --cached
git commit -m "content: 2026年08月月度整理"
git push origin main
```

`safe-publish.ps1` 只处理 `_vault`，不会清空其他已经暂存的代码改动。

### 步骤 7：清理 life-vault

网站和本地长期文件确认无误后：

```powershell
.\tools\monthly-migration.ps1 -Mode Finalize -MigrationId 2026-08 -ConfirmCleanup
git -C ..\life-vault status --short
git -C ..\life-vault diff
```

Finalize 只删除 manifest 中已经复制、有本地备份且哈希未变化的源文件。人工检查后再提交 `life-vault`：

```powershell
git -C ..\life-vault add -A
git -C ..\life-vault commit -m "cleanup: 2026年08月已归档"
git -C ..\life-vault push
```

## 5. 发布规则

```yaml
published: true   # 允许公开
published: false  # 仅宿舍本地长期保存
```

以下情况全部阻止发布：

- 缺少 `published`；
- 写成字符串 `"true"`；
- 同一文件重复出现 `published`；
- front matter 不存在或损坏；
- 本地图片引用不存在。

模型不能把 `false` 改成 `true`。公开是用户决定，不是内容分类的推论。

## 6. 文件与层级规则

- A/B/C 前缀只用于文件夹排序；
- 新文章不再强制增加 D 编号；
- 时间记录：`YYYY年MM月DD日-简短标题.md`；
- 长期文档：`简短语义标题.md`；
- 旧的 `Dn-*` 与 `YYYY-MM-DD-*` 保留，避免一次性改 URL；
- 相对图片放在文章同目录；构建时自动复制到公开资源路径；
- 不清楚分类时保留在 `life-vault`，不默认塞进回忆归档。

机器可读规则：[config/vault-taxonomy.json](../config/vault-taxonomy.json)

## 7. 暂不启用定时任务

至少连续两个月手动完成以下验收后，才考虑月末自动触发：

- 没有文件丢失；
- 没有私密内容被暂存；
- 两个智能体失败后可以安全重跑；
- 人工复核时间不超过 30 分钟；
- 分类 `retain` 比例可接受；
- `safe-publish -DryRun` 与正式暂存结果一致。

即使以后定时触发，正式发布和 Finalize 仍保留人工确认。

## 8. 故障处理

| 情况 | 行为 |
|---|---|
| Git pull 冲突 | 停止，人工解决 |
| 模型 JSON 无效 | 丢弃计划，重新生成；源文件不受影响 |
| 分类不确定 | `retain` |
| 目标已存在且不同 | Apply 停止，禁止覆盖 |
| 整理产生幻觉 | 从 `source-backup` 对照或恢复目标副本 |
| 发布字段缺失 | 默认私密并阻止发布 |
| 图片缺失 | 阻止发布 |
| 推送失败 | 保留本地提交，网络恢复后重试 |

## 9. 验收标准

本计划完成的定义：

- life-vault 当月文件全部被 `migrate` 或明确 `retain`；
- migrated 文件都有哈希备份和目标文件；
- Vault 校验 0 error；
- 发布暂存区没有 `published: false` 或状态不明文件；
- GitHub Pages 构建通过；
- Finalize 后 life-vault 只剩保留项和基础结构。
